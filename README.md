# Creator Analytics — прототип с бекендом

Прототип `test-creator222.vercel.app` (файл `PROTOTYPE_ORIGINAL.html` — нетронутая копия
для сравнения) со «прикрученным» бекендом на Express. Лендинг **не менялся ни на байт**
(проверено побайтовым diff'ом markup до `<script>`). Изменения — только в разделах
кабинета креатора, клиента и админки: вместо хардкод-массивов в JS теперь идёт
`fetch('/api/bootstrap')` и запросы на мутации.

## Структура

- `public/index.html` — фронтенд (бывший прототип, доработанный).
- `server.js` — точка входа Express.
- `server/store.js` — данные в памяти процесса (никакой БД). Каждый блок данных
  помечен комментарием `TODO(DB): ...` — где и как потом подключить настоящую БД
  (таблица/поля), когда это понадобится.
- `server/routes/api.js` — все `/api/*` эндпоинты, бизнес-логика скопирована 1:1
  с оригинальных JS-функций прототипа (расчёт выплат, синхронизация выплата↔вывод↔баланс,
  уведомления и т.д.).
- `render.yaml` — блюпринт для деплоя на Render (Node, free-план).
- `full_check.mjs` — сквозной Playwright-тест (лендинг + все разделы админки/креатора/клиента).

## Локальный запуск

```
npm install
npm start
# http://localhost:3000
```

## Тесты

```
npm install
node full_check.mjs   # требует playwright (npm i playwright, один раз)
```

## Важно

- Данные живут только в памяти процесса — перезапуск сервера сбрасывает их к исходным
  тестовым значениям (это специально, БД сознательно не подключена).
- Все точки будущего подключения БД помечены `TODO(DB)` в `server/store.js`.
